# 概念质量规则

“概念”必须提出可辨认的抽象、机制、方法或问题定义，并能由证据回答它是什么、
为什么重要、解决什么问题，以及它相对既有方案的相同点、差异、适用时机和
非替代边界。新闻、教程、产品发布和观点随笔不自动构成概念。

## 硬过滤

- 无原始出处，正文截断且无法补全，或核心证据不可访问。
- 只有代码、命令、链接集合或宣传信息，没有概念机制。
- 核心字段无法按 evidence policy 获得直接支持。
- 找不到具体对比对象或可核验的对比来源。
- 只是既有常识的改名、转载、翻译或轻微改写。
- 作者池模式中与配置主题明显无关。

## 评分

| 维度 | 范围 | 判断 |
|---|---:|---|
| novelty | 0–3 | 抽象、机制或问题定义的独特程度 |
| problem_clarity | 0–2 | 旧方法、约束或痛点是否明确 |
| mechanism_clarity | 0–2 | 原理、步骤或因果机制是否明确 |
| evidence_quality | 0–2 | 证据是否充分、直接、可回溯 |
| source_authority | 0–1 | 是否为原创者或一手来源 |
| promotional_penalty | 0 至 -3 | 宣传性越强扣分越多 |

默认总分至少 6，且 `novelty` 与 `problem_clarity` 均不得为 0。多来源描述同一概念时，
合并为一张卡片，并优先采用原始论文、规范、作者原文或一手实现文档。
